# Reproduce the search inside ProQuest TDM Studio

1. In an authorized TDM Studio Workbench, create a **new** search in ProQuest Dissertations & Theses Global. Paste the entire expression from `topical_query.txt` as one query. Set Date Published to **1 January 2010–31 December 2023**. Record the execution date and every interface filter; you may also record the displayed result count as provenance.
2. Export the search results as both record XML and **Extended Metadata CSV** into that Workbench, from the same search. Do not use an old worker assignment, a historical GOID list, a reference CSV or the original study's 21,073-record roster. The metadata CSV needs the columns `GOID`, `Title`, `Authors` (or `Author`), `Date`, `Degree Date`, `Language`, `School Location` and `Source Type`. The XML needs `GOID`, `Obj/TitleAtt/Title` and `Obj/Abstract`. If Studio produces other column names, adapt and document the importer before preparing a run; do not guess silently.
3. Upload and open `START_HERE.ipynb` in the same Workbench. In section 1, set `XML_DIR` and `METADATA_CSV` to those new exports, enter the search execution time and exact interface filters, then set `PREPARE_FROM_MY_SEARCH=True`. The script matches XML and metadata by GOID and applies these rules in order:
   - Dissertations & Theses document type; Date Published 2010–2023; English language; Degree Date 2010–2023; U.S. School Location, excluding UK & Ireland. A record missing the value that a rule needs is excluded at that rule, with the reason recorded.
   - Abstracts are present, blank or placeholder under the codebook's A5 rule: whitespace collapsed, case folded, terminal full stops removed, then an exact match with `abstract not available`, `no abstract available`, `no abstract provided` or `abstract unavailable`.
   - Records sharing a normalized title–author–completion-year key are one work. The copy with an abstract is kept, then the lowest GOID. Records without a title or author are kept and flagged rather than merged.
   - Records found only in the XML or only in the metadata, or repeated in the XML, are excluded and recorded. A title that still differs between XML and metadata after markup and entities are removed is flagged; the record is kept, with the XML as its evidence.

   Result counts and missing values never stop preparation. It creates a **new, private** roster, reference and worker assignment from the retained search results; they are not distributed in this package.
4. Inspect the private audit, removals and review flags before coding. Review placeholder abstracts, duplicate-work decisions and flagged titles. Do not treat a preflight success as confirmation that the new search equals the historical collection. Then follow sections 2–3 for scope coding, content coding and accounting.

The original historical input was assembled from overlapping brief-citation passes and a separate TDM export; the raw pass files and exact dates are unavailable. A new combined-query run can therefore differ in coverage even if its total resembles the original count. `Date Published` and `Degree Date` are different fields. This rerun records its own denominator and must be labeled a **new search-derived replication**. Keep XML, metadata, identifiers, titles, abstracts, assignments and checkpoint outputs in restricted TDM Studio storage. Use the approved results route for any permitted export.
