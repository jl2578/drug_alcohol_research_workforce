# Private reviewer search and coding rerun

Use `START_HERE.ipynb` **inside an authorized ProQuest TDM Studio Workbench**. First run a new search with `search/topical_query.txt` and follow `search/REVIEWER_SEARCH.md`. Export both XML and Extended Metadata CSV from that same search. The notebook's `prepare_from_search` route needs those exports, not a supplied reference CSV or historical GOID list. It refuses to overwrite an existing frozen plan. Generated reference text, roster, assignments, exclusions, hashes and coding checkpoints stay under `private/` in the Workbench.

The metadata export must contain the columns GOID, Title, Authors/Author, Date, Degree Date, Language, School Location and Source Type. Preparation stops only if one of those columns is absent or no assessable record remains; result counts and missing values never stop it. It applies the rules in `search/REVIEWER_SEARCH.md`, writing each excluded GOID and its reason to `search_removals_PRIVATE.csv` and each flagged record to `search_review_flags_PRIVATE.csv`; `search_audit_PRIVATE.json` gives the counts. Review duplicate-work, flagged-title and missing-abstract decisions before live calls. Placeholder abstracts follow the codebook's A5 list; inspect any other abstract boilerplate in the private evidence before coding.

The revision-15 codebook assesses substance-related and endogenous-system aims in one scope pass. The scope response supplies every unit's six S1–S4 fields plus record-level S5. Software validates, normalizes and derives inclusion and ordered targets from that response. Applicable but unsupported S4 remains `cannot_determine`; this does not reverse coded endogenous inclusion. Content returns C1–C9 only for the fixed targets and cannot change any scope field, aim/sentence ID, outcome or target. The merged `scope_codes` is the complete scope assessment.

Use the titles and abstracts from your own search exports; the package does not supply replacement abstracts or a reference roster. Do not rebuild the new reference over a stopped checkpoint; resume the saved plan or start a separately labeled run.

For live coding, supply this Workbench's authorized TDM proxy URL, key-file **path** and measured pacing. Check access to the frozen stage models and projected cost; `README.md` explains workload, cost estimation and model-availability checks. Run scope with `RELEASE_CONTENT=False`; after reviewing progress, run the same identity with `RELEASE_CONTENT=True` for content. The integrated HTTP 400 guard applies to both stages and requires no installation. Confirmed policy refusals are saved as `content_filtered` record failures so other records continue. One isolated unclear JSON HTTP 400 can be deferred; another without an intervening validation stops. Configuration errors are fatal; quota and transient pauses preserve the checkpoint. Review failures and use the one-pass retry only deliberately. Unresolved failures block the standard final export and are not coded as undetermined.
